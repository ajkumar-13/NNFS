# Evaluation

Measured: 2026-10-05. Every figure on this page was printed by the commands shown, run from this directory in a freshly created environment, or is arithmetic on such figures (a count turned into a percentage, a difference of two counts). The code that prints them is `src/binary_classifier/train.py`, `src/binary_classifier/evaluate.py`, and `scripts/seed_sweep.py`.

## The claim

Trained from seed 0 with the documented command, the 337-parameter network classifies all 200 held-out points correctly at noise 0.1; the same command with `--init small` stops at 174 of 200; and over seeds 0 to 9 the He runs score at least 197 of 200 while the small-initialisation runs score at most 181.

The first part is false if the commands below, run in the locked environment, print a lower accuracy. The last command makes that a check: it exits with status 1 when the test accuracy is under 1.

## How to reproduce it

```bash
uv sync --frozen
uv run python -m binary_classifier.train
uv run python -m binary_classifier.evaluate --min-accuracy 1.0
```

| Item | Value |
|---|---|
| Seed | 0 (the default of `--seed`), except under "Other seeds"; one seed fixes the data, the split, and the initial weights |
| Data | two moons generated by `src/binary_classifier/data.py`: 1,000 points, noise 0.1, split 800 to 200; SHA-256 `528b9a67c063e8c5d7fe246209911a5ba002d1ead954ddd517b109907fa1a43e` |
| Training | 2,000 full-batch epochs, He initialisation, Adam with learning rate 0.01 and no decay, L2 0.0001 on the hidden weights |
| Software | Python 3.13.5, NumPy 2.3.5, installed from `uv.lock` by uv 0.11.7 |
| Machine | Intel Core i7-9750H (2.60 GHz), 7.8 GB of memory, Windows 10, CPU only |

The second part of the claim holds: 174 of 200, which is 87.0 percent, with 707 of 800, 88.4 percent, on the training set. With `--min-accuracy 1.0` added, the evaluation of this file ends with `error: test accuracy 0.8700 is below the required 1.0000` and exit status 1.

The output also says what went wrong. The data are the same as in the first run, as the two `data sha256` lines show, and so are the standard normal draws behind the weights, which differ only by a positive factor per layer. With zero biases such a factor rescales the logit and leaves its sign alone, which is why both runs start at the same training accuracy, 0.7100. What the factor changes is the size of the logits. The small initialisation starts at a loss of 0.6931, which is $\ln 2$, the loss of answering one half for every point; its standard deviation of 0.01 is 100 times smaller than He's for the first layer ($\sqrt{2/2} = 1$) and 35 times smaller for the other two ($\sqrt{2/16} = 0.354$). From there the loss falls to 0.2480 by epoch 200 and is still 0.2472 at epoch 2,000.

What the network has become by then is a linear classifier. A plane fits its 800 training logits with $R^2 = 1.0000$ to four decimals, against 0.7413 for the documented run, so its decision boundary is a straight line, and no straight line separates two interleaved half-circles: 93 training points and 26 test points lie on the wrong side of it. Seven of the 16 units of the first hidden layer and five of the second are active on no training point; in the documented run the counts are none and one.

More epochs do not end the plateau. With ten times as many,

```bash
uv run python -m binary_classifier.train --init small --epochs 20000 --log-every 2000 --weights moons_small_long.npz
uv run python -m binary_classifier.evaluate --weights moons_small_long.npz --grid grid_small_long.npz
```

the training log still read `epoch 20000 | loss 0.2469 | train_acc 0.8838`, and evaluation printed `[train] loss 0.2467 | accuracy 0.8838 (707/800)`, `[test] loss 0.2646 | accuracy 0.8700 (174/200)`, and `R^2 1.0000`.

### A harder dataset

At noise 0.2 the gap between the two half-circles, 0.5 at their closest, is two and a half standard deviations of the noise, and the same network no longer fits every training point.

```bash
uv run python -m binary_classifier.train --noise 0.2 --weights moons_noise02.npz
uv run python -m binary_classifier.evaluate --weights moons_noise02.npz --grid grid_noise02.npz
uv run python -m binary_classifier.train --noise 0.2 --init small --weights moons_small_noise02.npz
uv run python -m binary_classifier.evaluate --weights moons_small_noise02.npz --grid grid_small_noise02.npz
```

| Run at noise 0.2 | Training set | Test set | Plane $R^2$ |
|---|---|---|---|
| He | 788 of 800 (98.5 percent), loss 0.0377 | 192 of 200 (96.0 percent), loss 0.1846 | 0.7005 |
| `--init small` | 702 of 800 (87.8 percent), loss 0.2799 | 170 of 200 (85.0 percent), loss 0.3033 | 1.0000 |

With He the test loss, 0.1846, is about five times the training loss, 0.0377. A gap of that size is what a validation set (`nn-029`) exists to watch; the project has none and trains for a fixed number of epochs.

## Repeatability

Every command on this page was run at least twice on 2026-10-05, in separately created environments, and printed the same output apart from the timing line: on this machine, with the locked packages, the result repeats bit for bit. The same six weight arrays, the same split, and the same decision grid also came out of the project's scripts as they stood before version 1.0.0, so restructuring the code into a package changed nothing in the model. They came out, too, of an environment with Python 3.12.12 and NumPy 2.5.3, the one other NumPy tried (record [0003](adr/0003-pin-numpy-for-bit-reproducibility.md)).

The third part of the claim holds. With He initialisation every seed fits all 800 training points and scores between 197 and 200 on the test set, 200 on eight seeds of ten. With the small initialisation no seed exceeds 181 of 200, 90.5 percent, and on every seed the network is a linear classifier to at least $R^2 = 0.9999$. The gap between the worst He run and the best small run is 16 test points.

Xavier initialisation, which `nn-033` derives for tanh hidden layers, does as well as He here: its lowest score is also 197 and its mean 199.5 against 199.6. Its standard deviations for the three layers are $\sqrt{2/18} = 0.33$, $\sqrt{2/32} = 0.25$, and $\sqrt{2/17} = 0.34$, within a factor of three of He's and at least 25 times the small one. The failure belongs to the scale 0.01, not to the choice between the two principled schemes.

## What the tests establish

The numbers above are only as good as the code that produced them. `uv run pytest --cov=src --cov-fail-under=95` ran 155 tests on the day of these runs and covered every line and branch of `src/`. Among them: the backward pass of every layer, and of the assembled network with its L2 terms, agrees with central-difference gradients; the dense layer, the sigmoid, the loss, the first two Adam steps, the confusion matrix, and the plane fit reproduce values worked out by hand; the generator reproduces a committed eight-point fixture; a training set of 48 points is fitted exactly in 300 epochs; and a pickle disguised as a weights file is refused without being executed.

## Limits of the claim

- **It is one run on a small test set.** The 100.0 percent is one seed, one dataset of 1,000 points, and a test set of 200, where one point is half a percentage point. The seed sweep puts the same configuration between 98.5 and 100.0 percent over ten seeds.
- **The task is easy and the test set is not independent data.** The test points come from the generator that drew the training points, and at noise 0.1 the two noiseless half-circles are 0.5 apart at their closest, five times the standard deviation of the noise. The score says that the network interpolates this distribution. It says nothing about other data.
- **No validation set was held out,** and the configuration was settled with the test score in view: the noise level and the initialisation were both changed on 2026-06-10, after the first configuration, noise 0.2 with the small initialisation, scored the 85 percent of the table above. Seeds 1 to 9, which the configuration was not chosen on, are the check.
- **The comparison of initialisations is narrow.** It holds for this network, this optimiser setting, and budgets up to 20,000 epochs for seed 0. It is not a statement that the small initialisation can never be trained: a different learning rate or a different optimiser was not tried here.
- **Bit-identity is local.** It was shown on one processor, under the locked NumPy 2.3.5 and under NumPy 2.5.3. On another processor the last printed digits of the losses may differ, and with them, in principle, a point that sits on the boundary. The `data sha256` line does not depend on the linear algebra library: if yours differs from the one above, the data themselves differ.
- **The training time is a wall-clock reading** on a laptop that was running other work at the same time. Read it as "one to three seconds", not more; the sweep of 30 runs took between 36 and 59 s.
