# 0004. Read the data from the original archive, fetched by a script and checked by SHA-256, without scikit-learn

- Status: accepted
- Date: 2026-10-05

## Context

Before version 1.0.0 the loader had two backends. The default called `sklearn.datasets.fetch_california_housing`, which made scikit-learn and SciPy dependencies of a project whose point is NumPy alone, downloaded the data the first time the trainer ran, and kept it in a cache in the user's home directory in a format of scikit-learn's own. The other backend downloaded `cal_housing.tgz` from a university mirror of StatLib with no check on what arrived; on 2026-10-05 that mirror did not answer. In both cases training could open a network connection, and nothing in the project tied a run to a particular set of bytes.

The documented result was produced through the scikit-learn backend. Replacing it is only acceptable if the replacement yields the same arrays, so this was measured before anything was changed.

- scikit-learn 1.9.0 downloads one file, `cal_housing.tgz`, of 441,963 bytes with SHA-256 `aaa5c9a6afe2225cc2aed2723682ae403280c4a3695a2ddda4ffb5d8215ea681`, the checksum scikit-learn itself records for it. The archive holds the StatLib table `CaliforniaHousing/cal_housing.data`, of 20,640 rows and nine columns, and a short description file.
- scikit-learn reads the table as 64-bit floats, divides rooms, bedrooms and population by households, and divides the value by 100,000. The old loader then rounded the result to 32-bit floats.
- The same archive, read with `tarfile` and `numpy.loadtxt` and put through the same arithmetic in the same order, gives arrays whose SHA-256 is equal to that of the arrays scikit-learn returned: the $20{,}640 \times 8$ features and the 20,640 targets are identical bit for bit.
- With that loader the standardised folds are identical to the ones in the old checkpoint, and the documented run gives the same weights and the same printed figures.

## Decision

1. There is one data path: the archive `cal_housing.tgz`. `data.ARCHIVE` records its name, size and SHA-256, and it is the only definition of the dataset in the project.
2. Only `download.py`, run through `scripts/download_california_housing.py`, opens a network connection, and only when the user runs it. It fetches the address scikit-learn uses, accepts `https` addresses only, stops a transfer that exceeds the recorded size, and moves the file into place only when its size and SHA-256 match.
3. `load_california_housing` checks the SHA-256 of the archive on every load, before opening it, and stops with the download command in the message when the file is absent or different. The trainer and the evaluation never fetch anything.
4. The loader reads the one table out of the archive into memory by its exact member name. Nothing is extracted to disk.
5. The feature arithmetic is done in 64-bit floats and rounded to 32-bit floats once, at the end, because that is the order that reproduces the documented arrays. The published value in dollars is kept beside each fold as 64-bit floats, so that the evaluation measures its errors against the file's own figures and not against a 32-bit round trip of them.
6. The archive lives in `cal_housing_cache/` under the directory the command is run from, or wherever `--data-dir` points. It is ignored by git and never committed, although at 441,963 bytes it is under the size at which the series' contract requires a download script; one path for data, with a checksum, is simpler to reason about than a committed copy and a fetched one.
7. The tests read a synthetic fixture of 40 rows in the same format, committed under `tests/fixtures/` and generated by `scripts/make_test_fixture.py`, with its own recorded checksum.

## Consequences

- NumPy is the only runtime dependency, and once the dependencies and the data are fetched the project runs with no network access.
- Every run starts from the same bytes, so a difference between two runs is never a difference in the data.
- A re-compressed or re-exported copy of the same table is refused, because the checksum is of the archive, not of the numbers. The user has to fetch the published file, which costs one command.
- The address can disappear. `--url` takes another `https` location that serves the same archive; the checksum makes any such source as trustworthy as the first.
- The scikit-learn backend, the manual backend and the `--backend` option are gone. A cache left by scikit-learn in the user's home directory is not read and can be deleted by its owner.
- The guarantee costs one extra pass over 441,963 bytes on every load.
