# 0004. Read MNIST from its four original files, fetched by a script and checked by SHA-256

- Status: accepted
- Date: 2026-10-05

## Context

Before version 1.0.0 the loader had two backends. The default asked scikit-learn to fetch the dataset from OpenML, which made scikit-learn and SciPy dependencies of a project whose point is NumPy alone, and left the content of the dataset to a remote service. The other backend downloaded the four original IDX files from a mirror the first time the trainer ran, with no check on what arrived. In both cases training could open a network connection, and nothing tied a run to a particular set of bytes.

The documented result was produced from the four IDX files. Whether the OpenML copy yields the same arrays in the same order was never checked, so it could not be offered as an equivalent route to the documented figures.

## Decision

1. There is one data path: the four gzip files of the original distribution (`train-images-idx3-ubyte.gz`, `train-labels-idx1-ubyte.gz`, `t10k-images-idx3-ubyte.gz`, `t10k-labels-idx1-ubyte.gz`). `data.MNIST_FILES` records each file's name, size and SHA-256, and it is the only definition of the dataset in the project.
2. Only `download.py`, run through `scripts/download_mnist.py`, opens a network connection, and only when the user runs it. It accepts `https` addresses only, stops a transfer that exceeds the recorded size, and moves a file into place only when its size and SHA-256 match.
3. `load_mnist` and `load_test_set` check the SHA-256 of all four files on every load, before parsing, and stop with the download command in the message when a file is absent or different. The trainer and the evaluation never fetch anything.
4. The files live in `mnist_cache/` under the directory the command is run from, or wherever `--data-dir` points. They are ignored by git and never committed.
5. The tests read a synthetic fixture of 12 training and 6 test images in the same format, committed under `tests/fixtures/` and generated by `scripts/make_test_fixture.py`, with its own recorded checksums.

## Consequences

- NumPy is the only runtime dependency, and once the dependencies and the data are fetched the project runs with no network access.
- Every run starts from the same bytes, so a difference between two runs is never a difference in the data.
- A re-compressed or re-exported copy of the same images is refused, because the checksum is of the gzip file, not of the pixels. The user has to fetch the published files, which costs one command.
- The mirror can disappear. `--base-url` takes another `https` location that serves the same four files; the checksums make any such mirror as trustworthy as the first.
- The guarantee costs one extra pass over 11,594,722 bytes on every load.
- The scikit-learn backend and the `--backend` option are gone.
